# Sample data for drill-down (round 3)

The seed JSON is still generated by `node tools/dump-seed.js backend/src/main/resources/seed` from the prototype's own
generators in `tools/proto-data.js`. Gap report: `node tools/seed-coverage.mjs` (before and after: `seed-coverage.md`).

## Taluk on every district-tagged row
- Register records, release orders (spend), tipline claims, ground feed, ad flags and press releases carry `taluk`
  when their district is a real district. Statewide/State rows have no taluk.
- The taluk is picked by a stable hash of the row id (FNV-1a with a murmur3 finaliser, over the district's taluks in
  reference order). Row ids: the register's id column. Bills use the RO number, so a bill sits in the same taluk as its
  release order. Feed items have no id, so they use district + note.
- Exceptions:
  - Field and folk shows already had a taluk and keep it.
  - Offices and staff rows (one District Information Office per district) take the headquarters taluk, which is the
    first taluk in the reference list.
  - The hand-written claims, feed items, flags and releases use a taluk their text names, if it names one. For example,
    "Women in Sindhanur" goes to Sindhanur and "(Manvi)" goes to Manvi.
- In the JSON, `taluk` comes right after the district key. Apart from that, every prototype row is byte-identical to before.

## Supplementary rows (`"supplementary": true` in the seed JSON only)
- Registers, except geo-all, empanelment, bills and offices:
  - A district with no rows gets one row.
  - After that, every taluk with no rows gets one row in that taluk.
  - Each row is a copy of a randomly chosen (seeded, deterministic) district row of the same register, so field
    distributions match the generator. It gets the next id in the series and the new district/taluk.
  - Generator rules are kept:
    - Social posts get "District handle, <district>".
    - Landslide advisories only go to the five ghat districts, and heatwave advisories only to the seven northern ones.
    - Outdoor sites are copied only from statewide vendors or the district's own vendor.
    - Field shows get "<taluk> GP n" as the village.
    - Archive ids follow AR-<year><serial>.
- Empanelment, bills and offices are tied to the vendor list, release orders and one office per district, so they get
  no per-taluk rows. They had no district gaps.
- Spend: missing taluks would be filled with copies of a release order of the same district (district vendor). This
  added no rows, because the 3,367 district orders already reach all 146 taluks once hashed. Spend totals are unchanged.
- Claims, feed, ad flags and releases get one row per district that had none (23 claims, 26 feed items, 26 flags and
  28 releases). They are written from short templates that name the district or taluk. To keep the prototype's live
  queues as they were, these rows are older and settled:
  - Claims are Published (False or Misleading) and 60–400 hours old.
  - Feed items are daily reports or field pulse, 20–240 hours old. There are no open escalations.
  - Releases are issued 48 hours ago and earlier. Their ids count down from REL-1858.
  - Ad flags are new RO/2026 numbers, Flagged.
- The `supplementary` marker is dropped when rows are loaded (RecordMapper / SampleDataLoader), so it is never stored
  or returned by the API.

## Backend
- The `taluk` column (nullable) is added to SpendOrder, Claim, FeedItem, AdFlag and PressRelease. The APIs return it
  as `taluk`. Register rows keep `taluk` in their data JSON.
- RecordMapper:
  - Keeps a taluk only if it belongs to the row's district (case is normalised).
  - On a non-field register, an invalid or stale taluk is dropped. This covers a district edit and statewide rows.
  - The field and folk register has its own taluk column, so an invalid taluk there is a 400 error.
- Uploads:
  - The spend dataset has a new optional "Taluk" column.
  - The field register's taluk column is now of type `taluk`.
  - FieldCoercer checks both against the row's district: "Not a taluk of <district>", or "Statewide rows have no
    taluk; leave it empty".
  - Release orders issued in the app and live claims, feed items and releases have no taluk. They count at district
    level, and geoOk keeps rows without a taluk at every taluk of their district.
- Press release numbers: the next issued number is still the prototype's REL-(1875 + releases issued), so the first new
  one is REL-1881. Only releases numbered REL-1859 and up count. PressTest was updated to the same rule.
- Existing databases: ddl-auto update adds the new columns, but old rows keep a null taluk. To get the drill-down
  data, start with an empty data dir.
